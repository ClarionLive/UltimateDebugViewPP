Filtering Basics

Master message filtering to focus on what matters most in your debug output.

Understanding Filters

Filters are the heart of effective debugging with UltimateDebugView++. They help you:

  • Focus on specific problems by showing only relevant messages
  • Remove noise from verbose applications
  • Highlight important events with colors
  • Automate debugging workflows with actions
  • Track patterns and anomalies over time

The Filter System

UltimateDebugView++ uses a three-tier filtering system:

  1. Message Filters: Filter based on message content
  2. Process Filters: Filter based on process name or ID
  3. Prefix Filters: Quick filters for common prefixes like [ERROR]

Filter Types

UltimateDebugView++ provides 11 different filter types, each with specific behavior:

Basic Filters

  • Include: Show ONLY messages that match this pattern. Multiple include filters are OR'ed together.
  • Exclude: Hide messages that match this pattern. Applied before Include filters.
  • Highlight: Apply custom colors to matching messages without filtering.

Advanced Filters

  • Token: Extract and display only specific parts of messages using regex groups
  • Track: Monitor specific patterns and track their frequency over time
  • Once: Show only the first occurrence of matching messages, suppress repeats
  • MatchColor: Legacy color matching (use Highlight instead)

Action Filters

  • Stop: Stop capturing when this pattern is matched (useful for breakpoints)
  • Clear: Clear the view when this pattern is matched
  • Beep: Play a sound alert when this pattern is matched
  • Bookmark: Automatically bookmark lines that match this pattern

Match Types

Each filter can use different matching algorithms:

Simple (Substring)

  • Basic case-insensitive substring matching
  • Fastest performance
  • Example: "error" matches "Error", "ERROR", "An error occurred"

Wildcard

  • Uses * (any characters) and ? (single character)
  • Good balance of power and simplicity
  • Example: "*[ERROR]*" matches any line containing [ERROR]
  • Example: "Thread-?" matches "Thread-1", "Thread-A"

Regular Expression

  • Full regex support with capture groups
  • Most powerful but slower
  • Case sensitivity optional
  • Example: "^\\[\\d{2}:\\d{2}:\\d{2}\\]" matches timestamps

Creating Filters

Using the Filter Dialog

  1. Click the Filter button on toolbar or press Ctrl+L
  2. Select the appropriate tab (Messages, Processes, or Prefixes)
  3. Click Add to create a new filter
  4. Configure the filter:
    • Text: The pattern to match
    • Type: Include, Exclude, Highlight, etc.
    • Match: Simple, Wildcard, or Regex
    • Colors: For Highlight filters
    • Enable: Toggle filter on/off
  5. Click OK to apply

Quick Filter Methods

  • Right-click a message: Quick menu with common filter actions
  • Select text + right-click: Create filter from selection
  • Ctrl+I: Quick Include filter from selected text
  • Ctrl+E: Quick Exclude filter from selected text
  • Ctrl+H: Quick Highlight filter from selected text

Filter Processing Order

Understanding filter order is crucial for complex filtering:

  1. Process Exclude: Remove unwanted processes first
  2. Process Include: Keep only wanted processes
  3. Message Exclude: Remove unwanted messages
  4. Message Include: Keep only wanted messages
  5. Once filters: Check for duplicates
  6. Highlight filters: Apply colors
  7. Action filters: Execute actions (Bookmark, Beep, etc.)

Practical Examples

Example 1: Focus on Errors

Filter 1:
Type: Include
Pattern: error|exception|fail|fatal|critical
Match: Regex (case insensitive)
Result: Shows only error-related messages

Filter 2:
Type: Highlight
Pattern: FATAL|CRITICAL
Match: Simple
Color: Red background
Result: Critical errors stand out

Example 2: Clean Database Debugging

Filter 1:
Type: Exclude
Pattern: keepalive|ping|heartbeat
Match: Simple
Result: Remove noise

Filter 2:
Type: Include
Pattern: (SELECT|INSERT|UPDATE|DELETE|CREATE|DROP)
Match: Regex
Result: Show only SQL operations

Filter 3:
Type: Highlight
Pattern: ERROR.*SQL
Match: Regex
Color: Red text
Result: Highlight SQL errors

Example 3: Performance Monitoring

Filter 1:
Type: Include
Pattern: Duration: (\d+)ms
Match: Regex
Result: Show timing messages

Filter 2:
Type: Highlight
Pattern: Duration: ([5-9]\d{2}|\d{4,})ms
Match: Regex
Color: Yellow (slow: 500-999ms)

Filter 3:
Type: Highlight
Pattern: Duration: \d{4,}ms
Match: Regex
Color: Red (very slow: 1000+ms)

Example 4: Multi-Process Debugging

Process Filter:
Type: Include
Pattern: MyApp.exe|MyService.exe
Match: Wildcard

Message Filter:
Type: Exclude
Pattern: TRACE|VERBOSE
Match: Simple
Result: Show only important messages from specific processes

Prefix Filters

Prefix filters provide quick filtering for common message prefixes:

Default Prefixes

  • [ERROR] - Red highlight
  • [WARNING] - Yellow highlight
  • [INFO] - Blue highlight
  • [DEBUG] - Gray highlight
  • [SQL] - Triggers SQL formatting
  • [TRACE] - Light gray

Custom Prefixes

Add your own in Preferences → Prefix Filters:

  • [SECURITY] - For security events
  • [PERF] - For performance metrics
  • [AUDIT] - For audit trail
  • [CUSTOM] - Your application-specific prefixes

Filter Management

Filter Sets

  • Save: Save current filters to a .dvf file
  • Load: Load previously saved filter set
  • Clear All: Remove all filters
  • Reset Prefixes: Restore default prefix filters

Enable/Disable

  • Temporarily disable filters without deleting
  • Checkbox next to each filter in the list
  • Useful for comparing filtered vs. unfiltered views

Performance Tips

Filter Optimization

  • Use Exclude first: Reduce message volume early
  • Simple over Regex: Use Simple match when possible
  • Specific patterns: More specific = faster matching
  • Process filters: Filter by process before message content

High-Volume Scenarios

  • Start with aggressive Exclude filters
  • Use Process filters to limit sources
  • Avoid complex regex in Include filters
  • Consider using multiple views with different filters

Advanced Techniques

Token Extraction

Use Token filter with regex groups to extract data:

Pattern: User \[([^\]]+)\] logged in from ([0-9.]+)
Type: Token
Result: Extracts username and IP address

Duplicate Suppression

Use Once filter to see unique messages only:

Pattern: .*
Type: Once
Result: Each unique message shown only once

Conditional Actions

Combine filters for complex behavior:

Filter 1: Include "Starting process"
Filter 2: Beep "ERROR"
Filter 3: Stop "FATAL"
Result: Monitor startup, alert on errors, stop on fatal

Troubleshooting Filters

No Messages Showing

  • Check if Include filter is too restrictive
  • Verify Exclude isn't removing everything
  • Ensure filters are enabled (checkbox)
  • Check filter order (Exclude before Include)

Wrong Messages Highlighted

  • Regex may be matching more than intended
  • Check case sensitivity settings
  • Verify wildcard patterns
  • Test regex in Regex Helper (Ctrl+R)

Performance Issues

  • Too many complex regex filters
  • Move Exclude filters to top of list
  • Use Process filters to pre-filter
  • Consider simpler match types
Pro Tip: Create different filter sets for different debugging scenarios. Save them as .dvf files and quickly switch between them using Load Filter.

Best Practices

  • Start simple, add complexity as needed
  • Document complex regex patterns
  • Save useful filter sets for reuse
  • Use color coding consistently
  • Test filters on sample data first
  • Combine multiple filter types for precision
  • Review and clean up old filters periodically
