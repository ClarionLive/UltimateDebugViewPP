Win32 OutputDebugString Capture

Capture debug messages from Windows applications using the OutputDebugString API - the standard Windows debugging interface.

Understanding OutputDebugString

OutputDebugString is a Windows API function that allows applications to send debug messages to any attached debugger. UltimateDebugView++ acts as a system-wide debugger to capture these messages without interfering with application execution.

How It Works

The capture mechanism uses Windows shared memory and event objects:

  • DBWIN_BUFFER: A 4KB shared memory region for message data
  • DBWIN_BUFFER_READY: Event signaling the buffer is ready for new data
  • DBWIN_DATA_READY: Event signaling new data is available
  • Process ID: Included with each message for identification

Capture Modes

Local Capture (Default)

Captures messages from processes in your current Windows session:

  • Automatically starts when UltimateDebugView++ launches
  • No special privileges required
  • Captures from all processes in your user session
  • Ideal for application development and testing
  • Lower system overhead than global capture

Global Capture

Captures messages from all Windows sessions system-wide:

  • Enable: Log → Capture Global Win32
  • Requires administrator privileges
  • Includes system services and other user sessions
  • Essential for debugging services and system components
  • Higher message volume and system overhead
Important: Only one application can capture OutputDebugString at a time. If another debugger is running, UltimateDebugView++ won't receive messages.

Starting and Stopping Capture

Automatic Start

By default, local Win32 capture starts automatically when you launch UltimateDebugView++. No configuration needed.

Manual Control

  • Pause/Resume: Press Pause key or Log → Pause
  • Global Mode: Log → Capture Global Win32 (toggle)
  • Status Check: Look for "Win32: Active" in status bar

Using OutputDebugString in Your Code

C/C++ Example

#include <windows.h>

// Simple message
OutputDebugString(L"Application started");

// Formatted message
wchar_t buffer[256];
swprintf_s(buffer, L"Processing item %d of %d", current, total);
OutputDebugString(buffer);

// ANSI version
OutputDebugStringA("Debug message");

C# / .NET Example

using System.Diagnostics;

// Debug class (only in debug builds)
Debug.WriteLine("Debug message");
Debug.WriteLine($"Value: {myVariable}");

// Trace class (always available)
Trace.WriteLine("Trace message");
Trace.TraceError("Error occurred: " + exception.Message);

Clarion Example

! Using UltimateDebug class
ud.Debug('Processing customer: ' & CUS:Name)

! Direct API call
OutputDebugString('Direct debug message')

Python Example

import ctypes

# Direct Windows API call
ctypes.windll.kernel32.OutputDebugStringW("Python debug message")

# Or use a wrapper
def debug_print(msg):
    ctypes.windll.kernel32.OutputDebugStringW(str(msg))

PowerShell Example

# Using .NET Framework
[System.Diagnostics.Debug]::WriteLine("PowerShell debug")

# Or using Windows API
Add-Type @"
    using System.Runtime.InteropServices;
    public class Win32 {
        [DllImport("kernel32.dll", CharSet=CharSet.Auto)]
        public static extern void OutputDebugString(string message);
    }
"@
[Win32]::OutputDebugString("Direct API call")

Message Format

Each captured message includes:

  • Timestamp: Precise time with millisecond resolution
  • Process Name: Executable name (e.g., "MyApp.exe")
  • Process ID: Numeric process identifier
  • Message Text: The actual debug string (up to 4KB)

Performance Characteristics

  • Throughput: Handles 50,000+ messages per second
  • Latency: Near-zero delay from send to display
  • Buffer Size: 4KB per message (Windows limitation)
  • Threading: Dedicated capture thread prevents UI blocking
  • Memory: Efficient circular buffer management

Common Issues and Solutions

No Messages Appearing

CheckSolution
Another debugger attached?Close Visual Studio, WinDbg, or other debuggers
Capture enabled?Verify "Win32: Active" in status bar
Admin rights for global?Run as administrator for global capture
Process filters active?Check Log menu for process filters
Messages filtered out?Review include/exclude filters

Missing Some Messages

  • Buffer Overflow: Very rapid message bursts may overflow the 4KB buffer
  • Process Filters: Check if specific processes are excluded
  • Message Filters: Verify filter rules aren't too restrictive
  • Timing: Messages sent before capture starts are lost

Access Denied Errors

  • Global capture requires administrator privileges
  • Some system processes require elevation even for local capture
  • Anti-virus may block debug message capture - add exception
  • Windows Defender may need exception for UltimateDebugView++

Advanced Features

Process Filtering

Focus on specific applications:

  • Include only certain process names
  • Exclude noisy applications
  • Use wildcards for process matching
  • Filter by process ID ranges

Message Prefixes

UltimateDebugView++ recognizes special prefixes:

  • [ERROR]: Highlighted in red
  • [WARNING]: Highlighted in yellow
  • [INFO]: Highlighted in blue
  • [SQL]: Triggers SQL formatting
  • Custom: Define your own in Preferences

Integration with Clarion

Enhanced support for Clarion applications:

  • Automatic procedure tracking
  • Structured message parsing
  • Thread identification
  • Performance profiling

Best Practices

  • Use Prefixes: Add [ERROR], [INFO] etc. for easy filtering
  • Include Context: Add thread ID, module name for complex apps
  • Avoid Flooding: Don't output in tight loops
  • Clean Up: Remove or disable debug output in production
  • Use Conditionals: Wrap in #ifdef DEBUG or similar
  • Message Length: Keep under 4KB to avoid truncation

Security Considerations

  • Debug messages are visible to any user with debugger privileges
  • Never output sensitive data (passwords, keys, PII)
  • Disable debug output in production builds
  • Be aware that debug strings consume system resources
Tip: Create a debug output wrapper class in your application to centrally control debug output, add automatic prefixes, and easily disable in production.
