Preferences

Configure default settings for new views and customize UltimateDebugView++ behavior.

Overview

The Preferences dialog (File → Preferences) provides comprehensive configuration options that apply to all new views you create. These settings define the default behavior and appearance of UltimateDebugView++.

Accessing Preferences

  • Select File → Preferences... from the menu
  • Or use the keyboard shortcut (if configured)
  • The Preferences dialog opens with multiple tabs

Preferences Tabs

1. New View Defaults

Configure default settings for newly created view tabs:

View Options

  • Show detail pane by default: Automatically display the detail pane in new views
  • Default splitter position (%): Set the initial size ratio between message list and detail pane (e.g., 75% for messages, 25% for details)
  • Word wrap: Enable text wrapping in the detail pane
  • Syntax highlighting: Automatically highlight code syntax in messages
  • Format content: Auto-format SQL and other structured content
  • Show line numbers: Display line numbers in the detail pane

Font Settings

  • Select Font button: Choose the default font for detail panes
  • Font Preview: See how your selected font will appear
  • Font settings include family, size, and style

Theme Selection

  • System Default: Follow Windows theme settings
  • Light: Force light theme regardless of system
  • Dark: Force dark theme for reduced eye strain

2. Prefix Filters

Manage default message prefix filters:

System Prefix Filters

Built-in filters for common message prefixes:

  • [ERROR] - Error messages (typically highlighted in red)
  • [WARNING] - Warning messages (typically in yellow)
  • [INFO] - Informational messages (typically in blue)
  • [DEBUG] - Debug output (typically in gray)
  • [SQL] - SQL queries (triggers formatting)
  • [TRACE] - Detailed trace information

Custom Prefix Filters

Add your own prefix filters:

  • Define custom prefixes for your applications
  • Set default colors and highlighting
  • Configure default filter actions
  • Create project-specific prefix patterns

Filter Management

  • Add: Create new custom prefix filter
  • Edit: Modify existing filters
  • Delete: Remove custom filters
  • Reset to Defaults: Restore system prefix filters

3. SQL Formatting

Configure how SQL queries are automatically formatted when detected in debug messages:

Keyword Case

  • UPPERCASE: SELECT, FROM, WHERE
  • lowercase: select, from, where
  • Capitalize: Select, From, Where

Indentation

  • Number of spaces: Set the number of spaces for each indent level (typically 2, 4, or 8)
  • Uses spaces for indentation (tabs not configurable in UI)
  • Affects nested queries, joins, and subqueries

Comma Alignment

  • Inline: Commas immediately after items
  • Trailing: Commas at end of line
  • Leading: Commas at start of next line

Format Style

  • Compact: Minimal line breaks, dense formatting
  • Normal: Balanced readability and space
  • Expanded: Maximum readability with more line breaks

Subquery Parentheses

  • Same line: Opening parenthesis on same line
  • New line: Opening parenthesis on new line
  • Indent content: Indent subquery content

Additional Options

  • New line before keywords: Add line breaks before major SQL keywords
  • Preview pane: See formatting changes in real-time with sample SQL

Applying Settings

Dialog Buttons

  • OK: Save changes and close dialog
  • Cancel: Discard changes and close
  • Apply: Save changes without closing

Scope of Settings

  • Settings apply to all new views created after saving
  • Existing views retain their current settings
  • Individual views can override defaults
  • Settings persist between application sessions

Best Practices

  • Configure preferences before starting a debugging session
  • Set up custom prefix filters for your application's conventions
  • Choose SQL formatting that matches your coding standards
  • Select a theme that's comfortable for extended use
  • Adjust splitter position based on typical message length

Tips

  • Use the Preview pane in SQL Formatting to test settings
  • Export preferences to share with team members
  • Create different configurations for different projects
  • Dark theme is recommended for long debugging sessions
  • Enable syntax highlighting for better code readability
Important: Preferences affect only new views. To update existing views, close and recreate them, or adjust their settings individually through the View menu.
