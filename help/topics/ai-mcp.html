AI Assistants (MCP)

Let an AI coding assistant such as Claude Code read, wait for and filter your debug output while it builds and tests your application.

UltimateDebugView++ has a built-in Model Context Protocol (MCP) server. An assistant connected to it can put a marker in the log, run your app, wait for the line it expects and read what happened, instead of asking you to copy messages or send screenshots.

Turning it on

  1. Open Preferences and choose the AI / MCP tab.
  2. Tick Enable MCP server. The default port is 7777.
  3. An access token is created automatically (press Generate for a new one). Every client must send it.
  4. Press OK. The status bar shows MCP :7777 while the server runs, or the reason it could not start (for example, the port is in use).

The server is off by default and only accepts connections from this computer (127.0.0.1).

Connecting Claude Code

Press Copy .mcp.json entry on the AI / MCP tab and paste it into .mcp.json in your project folder. It looks like this:

{
  "mcpServers": {
    "ultimate-debugview": {
      "type": "http",
      "url": "http://127.0.0.1:7777/mcp",
      "headers": { "Authorization": "Bearer <your token>" }
    }
  }
}

The headers line is required. You can also add it from a terminal:

claude mcp add --transport http ultimate-debugview http://127.0.0.1:7777/mcp --header "Authorization: Bearer <your token>"

Any MCP client that supports the Streamable HTTP transport can connect the same way.

What the assistant can do

ToolWhat it does
get_statusVersion, available tools, capture state, tabs and the current cursor.
read_messagesReads lines from the whole log or one tab, from a cursor onwards. Repeated identical lines are folded into one with a count.
wait_for_messagesWaits (up to 55 seconds per call) until a matching line arrives. The viewer stays responsive while it waits.
search_messagesFinds lines and returns each with the lines around it.
list_processesProcesses that wrote to the log, with line counts and first/last seen times.
insert_markerWrites a marker line such as === test 3 === to bracket a test run.
clear_log, pause_capture, resume_captureSame as the toolbar buttons.
list_tabs, create_tab, close_tab, switch_tab, rename_tabOrganise output into filtered tabs.
get_filters, set_filters, add_filter, remove_filter, enable_filterChange what a tab shows or highlights.
get_message_detailEverything about one line: Clarion fields, error fields, detected format and the formatted text (SQL pretty-printed with your SQL options).
jump_to_lineScrolls the viewer to a line and selects it, so you see the line the assistant is talking about.
set_bookmark, list_bookmarksMarks lines for you to look at.
get_procedure_statsClarion procedure open/close counts with the most unbalanced first (for example, a procedure opened twice), plus what is open right now.
get_procedure_timelineClarion procedure opens and closes in order, with call depth and durations.
list_queues, get_queueClarion queues dumped to the log by UltimateDebug.
create_procedure_viewOpens a tab showing one procedure's lines.
save_log, save_viewSaves the log or a tab as a new .dblog/.log/.txt/.csv file in the folder you chose (see below). The assistant only gives a file name; existing files are never replaced.

Where saved logs go

On the AI / MCP tab, under Logs the AI saves:

  • Choose My Documents (the default) or This folder: any existing folder, for example C:\Temp (use Browse...).
  • Add a Sub-folder such as DebugLogs; it is created when needed. In My Documents an empty sub-folder means UltimateDebugView.
  • Tick A folder per program to keep each program's logs apart, named after its exe: for example Documents\DebugLogs\PFBExec\run1.dblog.

When the assistant saves a log for one program, only that program's lines go into the file. With a folder per program and several programs in the log, the assistant shows you the list (with line counts) and asks which one you mean.

A typical test loop

  1. The assistant calls insert_marker and keeps the cursor it returns.
  2. It runs your application.
  3. It calls wait_for_messages with that cursor and a pattern such as ERROR|Main entered.
  4. It calls read_messages from the cursor to see everything the run logged.

Your tabs and filters are safe

  • Tabs the assistant creates are named AI: ....
  • It cannot change the filters of, rename or close your own tabs unless you ask it to (it then has to say so explicitly in the call).
  • The first tab can never be closed.

Security and privacy

  • Local only: the server listens on 127.0.0.1 and rejects requests from web pages on other sites.
  • Access token: always required, so other programs and other users on this computer cannot use the server. It is created for you when you enable the server.
  • Password masking: on by default. Values of PWD=, Password= / "password":, secret, token, api_key, Bearer tokens and passwords in URLs (user:pass@) are replaced by *** in everything the assistant receives, and its searches only see the masked text. This is best effort: it cannot recognise every kind of secret. The log on your screen is not changed.
  • No program launching: none of the tools can start programs or run commands.
  • Saved files are not masked: save_log and save_view write the log as captured, only into the folder you chose in Preferences. The assistant cannot choose another folder.
  • Everything the assistant reads is sent to its AI service, so only enable the server while you are using it.

Troubleshooting

  • Status bar says "MCP off: ...": the port is probably used by another program. Pick another port on the AI / MCP tab and update .mcp.json.
  • The assistant gets "401": the token in .mcp.json does not match the one in Preferences.
  • A call reports "did not respond within 15 s": a dialog is open in the viewer. Close it and try again.
  • Nothing is captured: check that capture is not paused (get_status shows paused).
