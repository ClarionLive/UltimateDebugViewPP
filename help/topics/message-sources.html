Message Sources

UltimateDebugView++ can capture debug messages from multiple sources simultaneously, providing a unified view of all debugging output.

Overview

Message sources are the various input mechanisms that feed debug messages into UltimateDebugView++. You can have multiple sources active at once, and each message is tagged with its origin for easy identification.

Managing Sources

Access source management through Log → Sources... to open the Input Sources dialog where you can:

  • View all active sources and their status
  • Add new sources (files, network connections, etc.)
  • Remove or pause individual sources
  • Configure source-specific settings
  • Monitor connection status and message counts

Available Source Types

1. Win32 OutputDebugString

The primary Windows debugging interface that captures messages from applications using the OutputDebugString API.

  • Local Capture: Default mode - captures from your user session
  • Global Capture: Enable via Log → Capture Global Win32 (requires admin rights)
  • Automatic: Starts capturing immediately when UltimateDebugView++ launches
  • Process Info: Each message includes process name and ID

Learn more about Win32 capture →

2. File Monitoring

Monitor text log files in real-time, similar to "tail -f" on Unix systems.

  • Real-time Updates: Automatically detects and displays new content
  • Multiple Files: Monitor several log files simultaneously
  • Network Paths: Support for UNC paths and mapped drives
  • File Rotation: Handles log rotation automatically

Learn more about file monitoring →

3. Network Sources

Receive debug messages over the network from remote applications or services.

UDP Socket Listener

  • Listen on any port (default: 9999)
  • No connection overhead - ideal for high-volume logging
  • Support for broadcast and multicast
  • Multiple simultaneous listeners on different ports

TCP DebugView Agent

  • Connect to Sysinternals DebugView Agent (port 2020)
  • Reliable connection with error detection
  • Optional compression for bandwidth savings
  • Password protection support

Access via Log → Connect DebugView Agent

4. Kernel Messages

Capture system-level debug output from drivers and kernel components.

  • Enable: Log → Capture Kernel Messages
  • Requirements: Administrator privileges
  • Verbose Mode: Log → Verbose Kernel Messages for detailed output
  • Pass-Through: Allow messages to reach other kernel debuggers

5. Named Pipes

Inter-process communication through Windows named pipes.

  • Create pipe servers or connect to existing pipes
  • Bidirectional communication support
  • Local and remote pipe connections
  • Automatic reconnection on disconnect

6. Process-Specific Sources

Monitor specific processes for targeted debugging.

  • Filter by process name or PID
  • Automatic child process tracking
  • Process start/stop notifications
  • Reduced noise from unrelated processes

Source Identification

Messages from different sources are distinguished by:

  • Process Column: Shows source process name and PID
  • Source Prefix: Optional prefix in message (e.g., [FILE], [NET])
  • Color Coding: Different sources can use different colors
  • Icons: Visual indicators for source type

Adding a New Source

  1. Open Log → Sources...
  2. Click Add button
  3. Select source type from dropdown
  4. Configure source-specific settings:
    • File path for file sources
    • Port number for network sources
    • Process name for process filters
  5. Click OK to start monitoring

Source Status Indicators

  • Green dot: Active and receiving messages
  • Yellow dot: Connected but idle
  • Red dot: Error or disconnected
  • Gray dot: Paused or disabled

Performance Considerations

Multiple Sources

  • Each source runs in its own thread for optimal performance
  • Messages are queued and processed asynchronously
  • No blocking between different sources
  • Automatic load balancing for high-volume sources

Buffer Management

  • Separate buffers for each source prevent overflow
  • Configurable buffer sizes per source type
  • Automatic old message pruning when limits reached
  • Memory usage monitoring in status bar

Troubleshooting Sources

Source Not Connecting

  • Check firewall settings for network sources
  • Verify file permissions for file monitoring
  • Ensure admin rights for kernel/global capture
  • Check if port is already in use for listeners

Missing Messages

  • Verify source is active (green status)
  • Check filters aren't hiding messages
  • Ensure buffer size is adequate
  • Look for connection errors in status

High CPU Usage

  • Reduce number of active sources
  • Apply filters to reduce message volume
  • Increase polling intervals for file sources
  • Disable verbose modes when not needed

Best Practices

  • Start with minimal sources and add as needed
  • Use process filters to reduce noise
  • Name your sources descriptively
  • Disable unused sources to save resources
  • Use different tabs for different source groups
  • Configure appropriate buffer sizes for expected volume
Tip: Create separate view tabs for different sources using the filter system. This helps organize complex debugging sessions with multiple active sources.
