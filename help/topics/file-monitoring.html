File Monitoring

Monitor log files in real-time and watch them update as applications write new content - like "tail -f" on Windows.

Overview

File monitoring allows UltimateDebugView++ to watch text log files and display new content as it's written. This is essential for debugging applications that write to log files instead of using OutputDebugString, including web servers, databases, and many enterprise applications.

Adding a File to Monitor

  1. Open Log → Sources...
  2. Click Add button
  3. Select File as source type
  4. Browse to select your log file or enter the path
  5. Configure monitoring options:
    • Keep Tailing: Continue monitoring for new content (recommended)
    • From Beginning: Load existing file content first
    • From End: Start monitoring from current end of file
  6. Click OK to start monitoring

Supported File Types

Text Log Files

  • .log: Standard log files
  • .txt: Text files
  • .out/.err: Output and error logs
  • No extension: Unix-style logs
  • Custom extensions: Any text-based file

Application Logs

  • IIS Logs: W3C extended log format
  • Apache Logs: Access and error logs
  • SQL Server: ERRORLOG files
  • Application-specific: Custom application logs

File Monitoring Features

Real-time Updates

  • Automatically detects when file is modified
  • Uses Windows file change notifications for efficiency
  • Minimal CPU usage even with many files
  • Configurable check interval (default: 100ms)

File Rotation Handling

Automatically handles common log rotation scenarios:

  • Rename rotation: log.txt → log.txt.1, new log.txt created
  • Date rotation: log-2024-01-15.txt → log-2024-01-16.txt
  • Size rotation: Detects when file is truncated and restarts
  • Continuous monitoring: Follows the active log file

Network Path Support

  • UNC paths: \\server\share\logfile.log
  • Mapped drives: Z:\logs\application.log
  • Automatic reconnection on network interruption
  • Cached reading for better network performance

Practical Examples

Web Server Logs

Monitor IIS or Apache access logs:

C:\inetpub\logs\LogFiles\W3SVC1\u_ex*.log
C:\Apache24\logs\access.log
C:\Apache24\logs\error.log

Common application log locations:

C:\ProgramData\MyApp\logs\application.log
C:\Users\%USERNAME%\AppData\Local\MyApp\debug.log
C:\Program Files\MyService\logs\service.log

Development Logs

Monitor build and debug output:

.\bin\Debug\trace.log
.\build\output.log
.\test-results\test-run.log

System Logs

Windows and service logs:

C:\Windows\System32\LogFiles\*.log
C:\Windows\Temp\*.log
C:\ProgramData\MySQL\data\error.log

Configuring File Monitoring

Reading Options

  • From Beginning: Read entire existing file first
    • Good for small files or first-time debugging
    • May cause delay with very large files
  • From End: Start from current position
    • Recommended for large active logs
    • Ignores existing content
  • Keep Tailing: Continue monitoring after reaching end
    • Essential for real-time monitoring
    • Should usually be enabled

Performance Settings

  • Poll Interval: How often to check for changes (milliseconds)
  • Buffer Size: Read buffer for each check
  • Max Lines: Limit lines kept in memory
  • Encoding: UTF-8, ASCII, Unicode detection

Working with Multiple Files

Monitoring Multiple Logs

  • Add each file as a separate source
  • Each file gets its own monitoring thread
  • Messages are merged chronologically
  • Use prefixes to identify source file

Wildcard Support

Monitor multiple files with patterns:

  • *.log: All .log files in directory
  • app-*.txt: All files matching pattern
  • error_????.log: Specific pattern matching

Filtering File Content

Pre-Processing

Filter lines before they enter the message buffer:

  • Include only lines with specific keywords
  • Exclude verbose or repetitive content
  • Transform log format for consistency

Source Identification

File messages can be identified by:

  • [FILE] prefix: Automatic file source marker
  • Filename in process column: Shows source file
  • Custom prefix: Add your own identifier
  • Color coding: Different colors per file

Common Issues and Solutions

File Access Errors

ErrorSolution
Access DeniedCheck file permissions, run as administrator if needed
File LockedEnsure file isn't exclusively locked by writer
Path Not FoundVerify file path and network connectivity
Sharing ViolationFile may be opened exclusively by another process

Missing Updates

  • Keep Tailing disabled: Enable to continue monitoring
  • File not changing: Verify application is writing to file
  • Buffer full: Increase message buffer size
  • Filters too restrictive: Check include/exclude filters

Performance Issues

  • Too many files: Limit simultaneous monitored files
  • Large files: Start from end instead of beginning
  • Network latency: Increase poll interval for network files
  • High update rate: Apply pre-filters to reduce volume

Best Practices

File Selection

  • Monitor only actively written files
  • Avoid monitoring system files unless necessary
  • Use specific paths rather than wildcards when possible
  • Consider file size and growth rate

Configuration

  • Start from end for large existing files
  • Always enable "Keep Tailing" for active logs
  • Use appropriate poll intervals (100-500ms typical)
  • Set reasonable buffer limits

Organization

  • Create separate tabs for different file groups
  • Use descriptive names for file sources
  • Apply filters to focus on relevant content
  • Color-code different file types

Advanced Techniques

Log Parsing

Extract structured data from logs:

  • Use regex filters to parse fields
  • Extract timestamps for chronological sorting
  • Parse log levels for highlighting
  • Extract error codes for filtering

Correlation

Correlate events across multiple files:

  • Monitor application and system logs together
  • Use timestamps to align events
  • Track request IDs across files
  • Create unified view of distributed systems

Automation

Automate file monitoring setup:

  • Save configurations with file sources
  • Use command-line to add files
  • Create templates for common scenarios
  • Script source addition via configuration files
Tip: For high-volume log files, use pre-filters to reduce the data before it enters UltimateDebugView++. This significantly improves performance and reduces memory usage.
