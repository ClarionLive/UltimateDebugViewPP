Network Sources

Receive debug messages from remote applications and services over the network using UDP sockets.

Overview

UltimateDebugView++ can receive debug messages over the network, allowing you to monitor applications running on remote machines or collect debug output from distributed systems. This is particularly useful for:

  • Debugging applications on servers or remote machines
  • Collecting logs from multiple systems in one place
  • Monitoring embedded systems and IoT devices
  • Debugging containerized applications
  • Creating centralized logging for distributed systems

UDP Socket Listener

The primary network source is the UDP socket listener, which provides:

  • Low overhead: No connection establishment required
  • Fire-and-forget: Applications can send messages without blocking
  • Multiple sources: Many applications can send to the same port
  • Network efficiency: Minimal protocol overhead
  • Real-time delivery: Messages arrive immediately

Default Configuration

  • Default port: 9999 (configurable)
  • Protocol: UDP/IP (SOCK_DGRAM)
  • Binding: INADDR_ANY (all network interfaces)
  • Buffer size: 2000 bytes per message
  • Threading: Overlapped I/O for efficiency

Setting Up UDP Listener

Adding a UDP Source

  1. Open Log → Sources...
  2. Click Add button
  3. Select UDP Socket as source type
  4. Configure the listener:
    • Port: Enter port number (default: 9999)
    • Description: Optional name for this source
  5. Click OK to start listening

Status Indicators

In the Sources dialog, the UDP listener shows:

  • Description: "Listening at UDP port [port]"
  • Status icon: Green when active and receiving
  • Message count: Total messages received
  • Source identifier: [UDP ip:port] for each message

Sending Messages to UltimateDebugView++

Message Format

UDP messages are simple text strings. Each UDP packet becomes one debug message. The sender's IP and port are automatically added as a prefix.

C/C++ Example

#include <winsock2.h>
#include <ws2tcpip.h>
#pragma comment(lib, "ws2_32.lib")

void SendDebugMessage(const char* message)
{
    WSADATA wsaData;
    WSAStartup(MAKEWORD(2, 2), &wsaData);

    SOCKET sock = socket(AF_INET, SOCK_DGRAM, IPPROTO_UDP);

    sockaddr_in dest;
    dest.sin_family = AF_INET;
    dest.sin_port = htons(9999);
    inet_pton(AF_INET, "127.0.0.1", &dest.sin_addr);

    sendto(sock, message, strlen(message), 0,
           (sockaddr*)&dest, sizeof(dest));

    closesocket(sock);
    WSACleanup();
}

C# / .NET Example

using System.Net;
using System.Net.Sockets;
using System.Text;

public static class RemoteDebug
{
    private static UdpClient udpClient = new UdpClient();
    private static IPEndPoint endpoint =
        new IPEndPoint(IPAddress.Parse("127.0.0.1"), 9999);

    public static void WriteLine(string message)
    {
        byte[] data = Encoding.UTF8.GetBytes(message);
        udpClient.Send(data, data.Length, endpoint);
    }
}

Python Example

import socket

def send_debug(message, host='127.0.0.1', port=9999):
    sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    sock.sendto(message.encode('utf-8'), (host, port))
    sock.close()

# Usage
send_debug("Application started")
send_debug(f"Processing item {item_id}")
send_debug(f"Error: {error_message}")

PowerShell Example

function Send-DebugMessage {
    param(
        [string]$Message,
        [string]$Host = "127.0.0.1",
        [int]$Port = 9999
    )

    $endpoint = New-Object System.Net.IPEndPoint(
        [System.Net.IPAddress]::Parse($Host), $Port)
    $udpClient = New-Object System.Net.Sockets.UdpClient
    $bytes = [Text.Encoding]::UTF8.GetBytes($Message)
    $udpClient.Send($bytes, $bytes.Length, $endpoint)
    $udpClient.Close()
}

# Usage
Send-DebugMessage "Script started"
Send-DebugMessage "Processing: $fileName"

Bash/Linux Example

#!/bin/bash
# Using netcat (nc)
echo "Debug message" | nc -u -w1 192.168.1.100 9999

# Using socat
echo "Debug message" | socat - UDP:192.168.1.100:9999

# Function for repeated use
debug_log() {
    echo "$1" | nc -u -w1 127.0.0.1 9999
}

debug_log "Application started"
debug_log "Processing file: $filename"

Network Configuration

Firewall Rules

To receive UDP messages, configure Windows Firewall:

  1. Open Windows Defender Firewall with Advanced Security
  2. Create new Inbound Rule
  3. Rule Type: Port
  4. Protocol: UDP
  5. Specific local ports: 9999 (or your chosen port)
  6. Action: Allow the connection
  7. Profile: Select appropriate networks
  8. Name: "UltimateDebugView++ UDP"

PowerShell Firewall Configuration

# Add firewall rule (run as administrator)
New-NetFirewallRule -DisplayName "UltimateDebugView++ UDP" `
    -Direction Inbound -Protocol UDP -LocalPort 9999 `
    -Action Allow -Profile Any

Multiple UDP Listeners

You can create multiple UDP listeners on different ports to:

  • Separate debug streams by application
  • Organize messages by environment (dev, test, prod)
  • Group messages by severity or component
  • Create dedicated channels for specific debugging

Example Port Organization

  • 9999: General debug messages
  • 9998: Error messages only
  • 9997: Performance metrics
  • 9996: Database queries
  • 9995: Security events

Message Display

UDP messages appear in UltimateDebugView++ with:

  • Process column: [UDP sender_ip:sender_port]
  • Message column: The received text
  • Time column: Local receive time
  • Automatic coloring: Different colors per source IP

Performance Characteristics

  • Throughput: Handles thousands of messages per second
  • Latency: Sub-millisecond on local network
  • Buffer: 2KB per message maximum
  • Threading: Non-blocking overlapped I/O
  • Memory: Efficient circular buffer management

Use Cases

Microservices Debugging

Collect debug output from multiple services:

// Service A (port 9999)
udpDebug.Send("OrderService: Processing order " + orderId);

// Service B (port 9998)
udpDebug.Send("PaymentService: Charging card " + last4);

// Service C (port 9997)
udpDebug.Send("ShippingService: Creating label " + trackingId);

IoT Device Monitoring

Receive status from embedded devices:

// Arduino/ESP32 example
udp.beginPacket(debugHost, debugPort);
udp.printf("Sensor: temp=%.1f humidity=%.1f", temp, humidity);
udp.endPacket();

Docker Container Logging

Forward container logs to host:

# In container application
logger = UdpLogger(host='host.docker.internal', port=9999)
logger.debug(f"Container {hostname}: Starting application")

Security Considerations

Network Security

  • Local only: Bind to 127.0.0.1 for local-only access
  • VPN/Tunnel: Use VPN for remote debugging
  • Encryption: UDP doesn't encrypt - avoid sensitive data
  • Authentication: No built-in auth - use application-level tokens

Best Practices

  • Never send passwords, keys, or PII via UDP
  • Use dedicated debug network interfaces when possible
  • Implement rate limiting in sending applications
  • Monitor for UDP flood attacks
  • Disable network sources in production environments

Troubleshooting

No Messages Received

CheckSolution
Firewall blocking?Add inbound UDP rule for port
Port already in use?Check with: netstat -an | findstr :9999
Correct IP address?Verify sender targets correct host
Network connectivity?Test with ping between machines
UDP listener active?Check green status in Sources dialog

Messages Truncated

  • UDP buffer limited to 2000 bytes per message
  • Split long messages into multiple packets
  • Consider TCP for large data transfers

Performance Issues

  • Reduce message frequency in sending application
  • Apply filters to reduce displayed messages
  • Use multiple ports to distribute load
  • Check network bandwidth and latency

Advanced Techniques

Structured Messages

Send JSON or structured data:

// Send JSON
var debug = new {
    timestamp = DateTime.UtcNow,
    level = "ERROR",
    component = "AuthService",
    message = "Login failed",
    userId = userId
};
SendUdp(JsonSerializer.Serialize(debug));

Message Routing

Create a debug message router:

class DebugRouter:
    def __init__(self):
        self.targets = {
            'error': ('debugserver', 9998),
            'info': ('debugserver', 9999),
            'perf': ('debugserver', 9997)
        }

    def send(self, level, message):
        host, port = self.targets.get(level, ('localhost', 9999))
        # Send to appropriate port based on level

Multicast Support

For broadcasting to multiple receivers:
